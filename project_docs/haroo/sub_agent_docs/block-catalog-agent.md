# 📑 하루(Haroo) 원자 & 완성 블록 통합 카탈로그 추출 Sub-Agent 지침 (Block Catalog Sub-Agent Reference)

본 문서는 하루(haroo) 프로젝트 내 현재 실제 구현되어 있는 **1계층 원자 컴포넌트(Atomic Components)** 및 **2계층 완성 마스터 블록(Master Blocks)** 목록을 실시간 스캔하여, 하나의 통합 카탈로그 파일 내에서 원소 컴포넌트와 완성 블록 모두를 보여주는 문서를 자율 추출 및 반환하는 '블록 카탈로그 추출 전문 서브에이전트'의 단독 실행 지침서입니다.

---

## 🎯 1. 역할 및 서브에이전트 실행 목적 (Agent Identity & Trigger)

* **실행 트리거**: 사용자가 *"원소 블록과 완성 블록 목록 반환/추출해 줘"*, *"블록 카탈로그 생성해 줘"*, 또는 *"block-catalog-agent.md 지침대로 진행해"* 명령을 내렸을 때 작동.
* **주요 목표**:
  1. `src/components/atoms/` 및 `src/components/blocks/` 디렉터리의 실제 소스 파일(Ground Truth)을 실시간 스캔.
  2. 원자 컴포넌트(`atom_*.tsx`) 및 마스터 완성 블록(`blk_*.tsx`)의 파일명, 대표 명칭, 세부 기능 설명을 정밀 추출.
  3. 추출 결과를 본 서브에이전트 문서와 동일한 경로(`project_docs/haroo/sub_agent_docs/`)에 **하나의 통합 파일(`BlockCatalogList.md`)**로 출력하여 원소 컴포넌트와 완성 블록 전체를 한눈에 볼 수 있도록 반환.

---

## 🔍 2. 스캔 및 통합 카탈로그 생성 프로토콜 (Execution Protocol)

### 1단계: 실시간 소스 코드 스캔 (Source Scanning)
* **원자 컴포넌트 대상**: `src/components/atoms/` 하위의 모든 `atom_*.tsx` 파일 파싱.
* **마스터 블록 대상**: `src/components/blocks/` 하위의 모든 `blk_*.tsx` 파일 파싱.
* **그라운드 트루스 보장**: 문서에 작성된 내용에 의존하지 않고, 항상 실제 소스 코드의 컴포넌트 주석 및 렌더링 로직을 직접 검증하여 최신 상태를 유지.

### 2단계: 단일 통합 파일 생성 및 반환 (File Output Specification)
본 서브에이전트는 스캔 결과를 이원화하지 않고, 아래 **하나의 단일 파일**로 작성하여 반환한다.

* **통합 카탈로그 파일 경로**: `project_docs/haroo/sub_agent_docs/BlockCatalogList.md`
* **파일 포함 구성**:
  - **섹션 1 [1계층 22종 원자 컴포넌트 목록 (Atomic Components)]**: 파일명, 컴포넌트 명칭, 세부 기능 및 레고 조립 용도 설명 표.
  - **섹션 2 [2계층 35종 완성 마스터 블록 목록 (Master Blocks)]**: 파일명, 대표 타이틀/유형, 세부 비즈니스 기능 및 설명 표.

---

## 🚫 3. 작업 제한 및 실행 환경 지침
* **소스 코드 수정 금지**: 본 서브에이전트는 소스 코드 및 구현 상태를 탐색하여 카탈로그 문서를 추출하는 전용 에이전트이므로, 프로덕션 소스 코드(`src/components/`)를 임의 수정하지 않는다.
* **응답 언어 규격**: 작성하는 카탈로그 문서 및 보고서 등 모든 출력 결과물은 무조건 **한국어**로 작성한다.
* **3-Way 동기화 원칙**: 코드베이스의 변동사항이 감지되면 즉시 통합 카탈로그 추출 파일(`BlockCatalogList.md`)을 업데이트하여 코드-테스트-문서 삼위일체를 완수한다.
